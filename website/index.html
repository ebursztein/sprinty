01 / WORK THAT OUTLIVES CONTEXT

A fresh session.
A familiar plan.

Compaction trims a conversation. Sprinty preserves the work record in an append-only local ledger: what was planned, what changed, who owns it, and which checks ran.

Resume the sprint to recover a compact briefing and the next work window. Your agent continues from recorded state, with less detective work.

  • Sprint, subsprint, and item IDs stay on disk
  • Notes, artifacts, dependencies, and evidence stay attached
  • Resume returns current work and useful next calls
Explore the workflow ↗

02 / COLLABORATION WITH CLEAR OWNERSHIP

More agents.
One shared picture.

Run several coding sessions against the same local sprint. Each agent gets a name. Each claimed item gets one owner. Claim generations stop a former owner from writing after a handover.

Potential stalls make quiet work visible. They never reassign it automatically. Progress, activity, and ownership history make a deliberate handover easier.

  • Automatic identity for ordinary MCP connections
  • Agent roster, claim ages, and explicit handovers
  • Claude plugin support for shared subagent connections
Separate worktrees keep separate sprint bindings. Stable identity across a restart depends on the client supplying a native session ID.

03 / PROOF BUILT INTO THE WORKFLOW

Close the loop.
Keep the evidence.

An item completes with a real resolving commit and declared verification. Sprinty runs executable gates, records their output, and builds the change map from Git.

At sprint close, it checks the work again and writes the canonical changelog. The result is a record you can review, resume, and trust.

  • Commit-backed changes and recorded gate output
  • Coverage and changelog at sprint close
  • A shared ETA that separates queue time from observed work
Timed-out gates are marked unverified. ETA is activity-derived and shows learning or paused states when appropriate.

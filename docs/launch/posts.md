## Show HN draft

Title: Show HN: Sprinty – a shared work record for AI agents across sessions

I built Sprinty because agent work can outlive a conversation: the plan gets lost, parallel sessions overlap, and "done" can be difficult to inspect.

Sprinty is a local MCP server with agent skills. It breaks work into sprints, subsprints, and tasks; tracks dependencies and exclusive claims; keeps decisions and progress on disk; and records resolving commits and check evidence. The dashboard lets you inspect what is happening.

It works with projects such as websites and research briefs as well as software. Your client runs the agents; Sprinty coordinates the work. Shared local sessions use one canonical repository and data directory. It does not automatically launch a swarm or guarantee that a passing check proves output quality.

There is a 45-second captioned walkthrough and three copyable starting prompts:
https://ebursztein.github.io/sprinty/demo.html
https://github.com/ebursztein/sprinty/tree/main/docs/examples

I'd like feedback from people whose agent work spans sessions or parallel workers: what do you currently lose at handoffs, and where would a tool like this add more ceremony than value?

## Community post draft

How do you keep an agent project organized after the first conversation?

I've been building Sprinty to make the work record survive the session. You can split an idea into manageable tasks, assign distinct agents, preserve decisions and handovers, and inspect the checks behind a completed item.

The public demo follows one website project from research and design through building and review. There are also starting prompts for a research brief and a small agent team.

It is open source and runs locally. Setup and a short walkthrough:
https://ebursztein.github.io/sprinty/

If you try it on a real project, the most useful feedback is where setup failed, whether the plan helped you continue in another session, and what you still had to coordinate manually.
